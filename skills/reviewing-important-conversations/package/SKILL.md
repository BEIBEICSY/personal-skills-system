# 重要沟通整理与复盘

## 使用前：检查新版

每次使用本 Skill，先解析其安装目录并运行：

```bash
python3 <skill-directory>/scripts/check_update.py
```

脚本用 Git 和用户已有凭据，对比本机 `VERSION` 与 `update.json` 指定的 GitHub 分支上的版本。按 `status` 处理：

- `up-to-date`：不提示，直接继续。
- `update-available`：在开始其他工作前，告诉用户当前版本、最新版本、`changes` 中每个新版本的简要改动，以及 `update_steps`；询问现在更新还是先用当前版本继续。不自动更新。用户选择更新时，执行更新步骤后重新读取新的 `SKILL.md` 再继续。
- `ahead`：用一句话说明本机版本比 GitHub 新（多半尚未推送），然后继续。
- `unknown`：用一句话说明无法检查及原因，然后继续。

检查不得阻塞用户的工作，也不得输出或记录任何凭据。

## 核心原则

忠实材料与后续理解分开；任何结论都能回到具体来源。适用于老板 one-on-one、同事协作、朋友深聊、伴侣和家庭沟通等非心理咨询场景。

明确属于心理咨询时，停止本流程，改用 `reviewing-therapy-transcripts`。不得同时更新沟通脉络与心理咨询价值观脉络。

## 开始前

1. 第一次实际使用时，先确认用户指定的资料位置。若未指定，建议建立独立的“沟通复盘”工作区；不得写入心理咨询目录或月度 lifelog。
2. 对象标识默认使用“关系＋称呼”，如“直属老板A”“朋友小林”；未经用户明确提供和允许，不擅自将真实姓名写入文件名。
3. 无法可靠识别对象时，集中询问一次：
   > 这是谁、你们是什么关系、希望文件中怎样称呼？
4. 无法确认沟通实际日期时，另行询问；不得用文件创建时间、导入时间或接收时间代替。不得把“日期待确认”作为长期正式归档。确需临时落盘时，明确临时状态与确认点；后续批量重命名前取得用户确认。
5. 若多次沟通混在同一材料中，先请用户确认是否拆分；同一天同一对象多次沟通时使用两位序号。

## 原子流程

用户说“整理”或“复盘”时，默认依次完成四个阶段：

1. 原始材料归档
2. 忠实原始记录
3. 单次沟通复盘
4. 双脉络更新：分别更新关系对象脉络与自我价值／沟通脉络

用户只要求“归档”“只转写”“只总结”或“只更新某一脉络”时，只做指定阶段，不擅自生成其他产物；但要同步更新索引中的材料状态，将缺失项标为“待生成”或“未存入”，不创建无效链接。每次新增、移动、重命名或实质更新材料后都维护索引。

例外：用户明确要求“仅在当前对话中分析且不保存”时，只执行阶段三；不确认存储位置，不写入任何文件，也不更新索引。

输出前必须读取同目录的 `templates.md`，且只读取本次所需阶段的模板。若该文件尚不存在，明确模板待后续创建，仍按本 Skill 的边界完成当前可完成部分，不自行创建模板。

## 阶段一：原始材料归档

支持：

- 录音或视频中的音频
- 聊天截图
- 导出的聊天记录或用户粘贴的聊天文本
- 用户对沟通过程的事后口述
- 同一次沟通的混合材料

原始材料、原始记录和复盘默认仅在本地处理。保留原始格式和文件；不覆盖或删除源文件，转换格式也保留源文件。未经明确许可，不上传、发布、分享或发送材料到第三方。截图中的第三方隐私不得扩散到不必要的摘要或文件名。批量移动、重命名或删除前必须确认。

## 阶段二：忠实原始记录

按来源处理：

- **录音／视频音频**：忠实转写；可靠时记录说话人和时间戳，保留有意义的停顿、打断、重复和改口；听不清或不确定处明确标记，不依据上下文补全。
- **聊天截图**：保留原图，只转录截图中可见的发送者、时间和文字；说明裁切、缺页、开头缺失、结尾缺失或上下文不连续，不补写画面外内容。
- **导出／粘贴聊天**：保留原始顺序、发送者与已有时间信息，不润色原话。
- **事后口述**：醒目标记“用户事后口述”，忠实保存用户记得的事实、体验和判断；不得将其重建为双方逐字稿或精确引语。
- **混合材料**：可归入同一次沟通，但每一段都保留来源类型和对应材料，不能把口述、截图与录音混成无来源文本。

不得虚构或擅自补全对象身份、实际日期、时间戳、情绪、承诺、责任人、期限或截止时间。材料不完整时说明已覆盖范围和缺失范围。

## 阶段三：单次沟通复盘

先按真实顺序还原沟通地图，再整理双方关注点、关键互动、沟通结果、我的变化与下次连接。全篇严格区分四层证据：

1. **明确表达**：材料中一方直接说出或用户明确口述的内容，注明说话者与来源。
2. **可观察互动**：材料可直接看到或听到的回应、打断、转折、沉默等，不赋予心理意义。
3. **工作假设**：基于证据提出的待验证理解，必须同时写出至少一种其他合理解释。
4. **AI 可选建议**：面向未来的建议、措辞或表达策略，明确标记“AI 可选”，不得伪装成双方共识或唯一答案。

复盘至少核对：

- 双方明确表达的目标、期待、顾虑、限制、需要与边界
- 有证据的关键互动及其他解释
- 共识、分歧、未回答问题和待核实事实
- 每项承诺或待办的原话／来源、内容、责任人、期限或时间状态、完成状态；不清楚时写“不明确”
- 必须跟进的事项与下次可带回的话题

默认整理材料中明确存在的待办和下次话题。除非用户要求，不默认生成多套表达策略或行动建议；确需提供时仅作为简洁的 AI 可选建议。

成长与变化可标为“新增、再次出现、深化、修正、矛盾、开放卡点或无新证据”。不得为了形成正向叙事而强行总结“更成熟了”。

## 权力关系

处理老板、管理者或其他掌握资源的一方时，除沟通内容外，记录材料能够支持的职位关系、决策权限、资源控制、绩效／考核关系和现实依赖。对方的评价、要求和决定按事实及来源记录。

权力不等于正确：不自动服从或合理化对方要求；权力差异也不等于恶意：不得据此推断对方动机、人格或心理问题。

## 阶段四：双脉络更新

### 关系对象脉络

每个持续关系对象单独维护，记录关系背景、对方明确表达过的期待／反馈／偏好／边界、我的明确目标／需要／边界、历次来源、承诺状态、未决问题及互动变化。它服务于关系连续性，不是人物画像。

### 自我价值／沟通脉络

跨关系按材料中自然形成的主题维护用户自己的价值、需要、边界和沟通变化。记录确认程度（明确确认／待验证假设）、议题状态（可标开放卡点）、变化状态、具体关系情境及来源。矛盾证据并列保留，不覆盖旧观点或强行统一；没有新证据时只记录“无新证据”或更新最后核对范围。

两套脉络必须分离：关系对象脉络不代替自我脉络，自我脉络不变成人物关系档案。沟通中的自我脉络还必须与心理咨询价值观脉络分离；只有用户明确允许且来源确实相关时才可相互引用，不自动复制、合并或把一套结论归入另一套。

禁止根据单次或重复出现的材料认定任何人的固定动机、固定价值观、人格、心理类型或“真实自我”。重复仅表示某种表达或互动在具体情境中再次出现。

## 完成前核对

- [ ] 明确表达、可观察互动、工作假设、AI 可选建议互不混淆
- [ ] 每项承诺／待办可溯源，责任人、期限与时间／完成状态均已检查
- [ ] 关系对象脉络与自我价值／沟通脉络分开
- [ ] 沟通脉络与心理咨询价值观脉络隔离
- [ ] 未虚构身份、日期、时间戳、情绪、承诺、责任人或截止时间
