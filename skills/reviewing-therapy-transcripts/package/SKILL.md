# 基于逐字稿复盘心理咨询

## 使用前：检查新版

每次使用本 Skill，先解析其安装目录并运行：

```bash
python3 <skill-directory>/scripts/check_update.py
```

脚本用 Git 和用户已有凭据，对比本机 `VERSION` 与 `update.json` 指定的 GitHub 分支上的版本。按 `status` 处理：

- `up-to-date`：不提示，直接继续。
- `update-available`：在开始其他工作前，告诉用户当前版本、最新版本、`changes` 中每个新版本的简要改动，以及 `update_steps`；询问现在更新还是先用当前版本继续。不自动更新。用户选择更新时，执行更新步骤后重新读取新的 `SKILL.md` 再继续。
- `ahead`：用一句话说明本机版本比 GitHub 新（多半尚未推送），然后继续。
- `unknown`：用一句话说明无法检查及原因，然后继续。

检查不得阻塞用户的工作，也不得输出或记录任何凭据。

## 目标

帮助作为来访者的用户重新看见咨询现场，加深对本次咨询的理解，并形成可以带回后续咨询验证的材料。

核心顺序：

1. **先还原**：按时间线说明本次谈了哪些事、如何转折。
2. **再理解**：只对有充分互动信号的关键时刻提出工作假设。
3. **后验证**：把解释交还给用户和后续咨询验证，不替用户定义自己。

输出不是病历、诊断或对“潜意识真相”的判定。

## 基本边界

- 逐字稿中的明确表达、可观察互动和心理解释必须分开。
- 所有深层解释都写成**工作假设**，不能写成事实。
- 每个工作假设都要提供逐字稿证据，并保留至少一种现实或心理层面的其他解释。
- 不要求每个话题都有潜台词、防御机制、依恋模式或理智—情感冲突。
- 不依据一次表达认定人格特质、依恋类型、心理障碍、潜意识动机或童年因果。
- 咨询师在逐字稿中提出的解释，也应注明“咨询师提出”，不能自动当作已经证实。
- 不把时间上的相邻写成因果。例如，谈到委屈后又谈失眠，不等于委屈导致失眠。
- 迟到、付款、预约、沉默和笑等细节可以有心理意义，也可能有现实原因；证据不足时不做移情判断。
- 没有时间戳时使用“开场／前段／中段／后段／结尾”，不得虚构时间。
- 逐字稿未提及的内容写“本次咨询未明确提及”或“未明确约定”。
- 将“咨询中明确约定”与“AI可选建议”严格分栏，绝不混写。
- “明确悬而未决的问题”只收录来访者或咨询师实际说出口的问题；根据担忧推导出的新问题必须放入“AI提供的可选探索问题”。
- 不强行生成价值观、下次议题或微行动。
- 如果用户明确要求行动建议、但咨询中没有约定，先写“未明确约定”，再提供至多一个低压力的观察或书写练习，标注为“AI可选建议”。除非用户明确要求，不建议其立即进行关系对话或作出重要决定。

## 信息标记

在分析时遵守以下证据层级；正文不必机械地给每句话加标签，但必须保持边界清楚。

- **明确内容**：说话者直接表达的事实、情绪、想法、愿望或约定。
- **互动观察**：逐字稿可观察到的停顿、重复、转折、回应和情绪变化。
- **工作假设**：根据明确内容与互动观察提出的可能理解。
- **AI可选建议**：咨询双方没有约定、由复盘额外提出的反思入口。

## 工作流程

### 1. 建立完整时间线

通读全部逐字稿后再归纳。不要逐段独立总结后机械拼接。

按对话自然转折合并话题块。每块回答：

- 话题如何被触发；
- 来访者谈了哪些事实与感受；
- 咨询师进行了什么回应、追问、澄清或解释；
- 来访者如何回应咨询师；
- 对话如何转向或暂时结束。

相邻内容属于同一议题时合并；同一主题后来重新出现时，注明“再次回到该主题”，保留真实顺序。

### 2. 选择关键时刻

只选择具有下列信号的片段深入：

- 某种说法、情绪或关系经验反复出现；
- 来访者明显停顿、改口、转移、笑、沉默或自我否定；
- 咨询师的回应引发了明显的靠近、抗拒、松动或新认识；
- 当前事件与过去经验被来访者或咨询师明确连接；
- 咨询结束时出现重要总结、未完成感或关系互动。

没有足够信号时，只做过程记录，不做深度解码。

### 3. 形成工作假设

每个关键时刻使用以下结构：

1. **逐字稿证据**：短引原话、时间点或具体互动。
2. **当时的体验**：优先记录来访者明确说出的情绪、想法、需要和身体感受；未说出的不得补齐。
3. **可能的理解**：使用“可能、或许、值得验证”等措辞。
4. **其他解释**：至少保留一种不依赖深层心理机制的解释。
5. **留给来访者验证**：邀请用户感受自己是认同、抗拒、困惑还是暂时无感。

不要为了显得深入而使用专业术语。确需提及“理智化、回避、投射、移情”等概念时，先描述具体行为，再将术语作为低确定性的辅助理解。

### 4. 提炼整次咨询

跨话题归纳时，关注：

- 反复出现的主题及其证据；
- 情绪在咨询中的变化轨迹；
- 咨询师的重要干预及来访者的响应；
- 本次出现的新认识、松动、抗拒或未完成感；
- 不同话题之间由谁提出了怎样的连接。

只写本次咨询呈现的状态或倾向，不将其固化为稳定人格结论。

### 5. 整理后续材料

严格区分：

- 来访者明确提出但尚未回答的问题；
- 咨询师明确提出但尚未展开的问题；
- 双方明确约定的下次议题；
- 双方明确约定的行动；
- AI根据复盘提出的可选探索问题。

如果用户只要求总结，不自动增加行动建议。如果用户希望加深反思，可以提供少量可选问题，但不能冒充咨询师布置的任务。

### 6. 核对跨次价值观脉络（工作区配置时）

本步骤只在工作区规则明确配置了价值观脉络文件时执行。它发生在单次复盘完成并保存之后，不替代或改写单次复盘。

1. 读取价值观脉络全文，不只读取最近更新。
2. 从本次总结的以下部分提取候选内容：
   - “本次的新认识或松动”；
   - “仍然卡住或没有展开的部分”；
   - “本次呈现的价值与需要”。
3. 回到本次时间线、关键时刻和逐字稿证据，使用两组可组合的信息标记：
   - **确认程度**：
     - **明确确认**：来访者直接说出或清楚确认；
     - **待验证假设**：咨询师提出、复盘推导或来访者尚未确认。
   - **议题状态**：
     - **开放卡点**：已经出现但没有充分展开或形成结论。
   明确开放卡点可以是来访者明确提出的，也可以来自尚待验证的理解。
4. 与已有主题逐一核对，将本次内容标记为：
   - **新增**：此前没有相近主题或观点；
   - **再次出现**：核心观点基本一致，新增一次独立证据；
   - **深化**：原观点获得更具体的条件、感受、需要或脉络；
   - **修正**：来访者明确调整过去的说法或理解；
   - **矛盾**：新旧观点暂时不能可靠合并，需要并列保留。
5. 按适用情况更新对应主题的当前理解、新认识或松动、开放卡点、跨次变化和来源索引；没有新证据的字段保持不变。
6. 保留旧观点、日期和来源，不用新结论覆盖历史。
7. 无法归入现有主题时才新建主题；没有新证据时不为制造更新而添加内容。
8. 更新价值观脉络顶部的“最后核对至”日期，并确认工作区索引入口有效。

跨次文档中的每条内容至少包含咨询日期、单次咨询总结链接，以及对应条目名称或可用时间戳。重复出现不能自动把“待验证假设”升级为“明确确认”；矛盾也不能自动解释为心理冲突。跨次再次出现或深化只表示某主题在特定咨询情境中反复出现，不得据此认定稳定人格、固定价值观、真实自我或本质属性。

## 特殊情况

### 逐字稿很长

先建立覆盖全文的时间线，再选择关键时刻。不能因为后半段更靠近上下文窗口而忽略前半段，也不能让深度分析挤掉“本次谈了哪几件事”。

### 逐字稿不完整或转写质量差

在开头说明缺失范围、说话人混淆或疑似错字。不能用推测补全听不清的内容。

### 出现安全风险

如果逐字稿明确出现自伤、自杀、伤人、虐待或其他紧迫风险，先客观指出逐字稿中的原始风险信息，不做浪漫化或象征化解读，并建议用户及时与咨询师或当地紧急支持取得联系。不要仅凭含糊隐喻推断风险。

## 输出前自检

- 是否先完整回答了“这次咨询按时间谈了哪几件事”？
- 是否记录了咨询师的干预以及来访者的实际响应？
- 是否把明确内容、互动观察和工作假设分开？
- 每个深层理解是否有证据、保留其他解释并邀请用户验证？
- 是否虚构了时间、情绪、因果、下次议题或行动？
- 是否把AI建议误写成咨询中的约定？
- 是否用了过度确定或病理化的语言？
- 如果工作区配置了价值观脉络，是否在保存单次复盘后完成了跨次核对？
- 跨次文档是否保留旧观点，并为新增、重复、深化、修正或矛盾提供了具体来源？

发现任一问题，修正后再输出。
